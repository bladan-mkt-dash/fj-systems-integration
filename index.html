How to read this pack (authority order)

If two pages seem to disagree, use the higher item on this list. Product “what should happen for each patient field” beats architecture diagrams.

  1. Goals (this page) — what success looks like for the practice.
  2. Field contracts ((field mapping registry and each field detail page) — the product rules for each Admin Check List attribute (where it lives, how it syncs, what counts as a gap).
  3. Ops guarantee ((operations reporting layer) — the Admin Check List must be delivered; sync alone is not enough.
  4. How it is wired (golden record, hub flow, GCP schematic, calendar sync) — implementation shape, not a place to invent field behavior.
  5. When it is built (build checklist and gantt) — phases and readiness, after the rules above.

For builders and AI coding agents: treat the field maps as the source of truth for sync. Do not invent credit-card, membership, or Call Outcomes behavior from the architecture pictures alone. Later, the registry should also exist as a machine-readable file (JSON) with short Given / When / Then acceptance checks per field — plain-language test scripts such as “Given no Athena card, When the report runs, Then show a Missing CC Athena gap.” You do not need to write those yourself; they are derived from the field maps at build time.

WooCommerce (Admin Check List v1): Out of Missing Demographics Executive Roll Up / Record Ledger field contracts. Woo may be used for golden-record identity match only when unifying store customers — it does not own ledger columns or gap rules. See field mapping registry.

Goals

  1. Goal 1 — Unify patient records. Enter once and keep identity consistent across AthenaNet, Zenoti, GoHighLevel, and WooCommerce, with AthenaNet as the golden source of truth.
  2. Goal 2 — Keep membership status outcomes synchronized across every connected system (cancels, terminations, and suspensions).
    • Goal 2a — Zenoti membership-renewal declines (Path D). On renewal-day card miss/decline, Zenoti Suspends the membership. The hub does not write Zenoti; it immediately mirrors Suspended + Credit Card Zenoti = No into BigQuery (Ledger + Roll Up) and GHL. Athena stays unchanged by the hub. Detail: Active Membership Path D · Credit Card.
  3. Goal 3 — Deliver the Admin Check List. A live, internal-only, HIPAA-conscious Admin Check List for the 5 Journeys Practice (staff access only) so missing demographics and daily operational exceptions surface automatically (see also the record ledger variant).
