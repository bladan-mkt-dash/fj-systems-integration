Goal 2a — Zenoti renewal decline (confirmed): Zenoti membership renewals are paid by the Zenoti Saved Card only (payment vault firewall — never use Athena Card On File for this charge). On payment failure on the membership renewal day (card missing, expired, or invalid/declined): Zenoti itself Suspends the membership (guest / user / membership) — hub does not write Zenoti. Hub immediately (real-time / visible on browser refresh): (1) publish to BigQuery so Ledger + Missing Demographics Executive Roll Up show cc_zenoti = no (historically accurate as far as Zenoti API allows), membership_zenoti = Suspended, and membership_athena / Active Athena still Yes while Athena remains Active (expected Path D window — not a Conflict); (2) set GHL Membership Cancellation Data → Membership Suspended (dropdown radio option Membership Suspended); (3) clear GHL Credit Card Zenoti / force cc_zenoti = no in reporting. Athena decision (confirmed for now — may revisit): Do not auto-write Athena Membership Status on Path D. Athena stays as-is (typically still Active) until staff manually set Membership Status out of Active / inactive. Dual ledger columns make that window visible without inventing a Conflict. This is not a cancel (Paths A–B stay Cancelled).

Manual ops after Path D (confirmed — not hub automation in v1): Within 7 business days of the renewal-day decline, admin staff attempt to collect a working Zenoti Saved Card. If the situation is still unresolved after that window, staff then manually deactivate membership in Athena (human error accepted in this iteration). The hub must not auto-deactivate Athena in v1, invent a countdown job, or charge Athena Card On File. During the collection window, Ledger shows Membership Zenoti Suspended + Active Athena Yes + CC Zenoti No — the expected ops prompt. Future (after confidence in real-time + history): automation may flip Athena inactive 7 business days after Zenoti Suspend — explicitly out of v1 / Day 0.

Suspended — two entry points: Path D (renewal decline, Goal 2a) and Path C (manual staff suspend in Zenoti). Both end in Zenoti Inactive → Suspended and the same GHL Membership Suspended mirror (set when Suspended; clear when no longer Suspended). Path D does not write Zenoti Suspended — Zenoti is already the source. Hub fans out Suspended + card-not-operable to BigQuery (Ledger/Rollup) and GHL only.

Two-way depending on trigger: Form-originated cancels authoritative in GHL first, then push to Athena/Zenoti. Phone-originated cancels authoritative in Athena first, then push to Zenoti/GHL. Do not create an endless loop — hub should stamp cancel source and skip echo writes.

Zenoti Inactive reason (confirmed): Automated cancels (Paths A–B) map to Cancelled only. Suspended is used for Path D renewal declines (Zenoti-native) and Path C manual suspend — never use Suspended for intentional cancels. Hub never writes Suspended into Zenoti.

UX note: Membership Cancellation Data must remain writable by the existing form integration. The Membership Suspended dropdown radio under Membership Cancellation Data is a one-way Zenoti→GHL mirror (system-driven set/clear). Do not apply the Call Outcomes hide/lock rule to Membership Cancellation Data (form cancel fields must stay writable).
