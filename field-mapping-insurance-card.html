Pattern: Dual Athena document images (front + back) + two independent one-way presence mirrors into GHL. Zenoti N/A. No image bytes pushed to GHL. Athena is golden record for these attributes — GHL options stay unchecked (or are cleared) when Athena images are absent.

Post-integration UX (GHL): After go-live, Insurance Card Front / Insurance Card Back options must be hidden or unclickable (integration-owned). Staff must not toggle them — that would create mismatches against Athena. Only the hub sets/clears each option from Athena Front/Back image presence.

Confirmed rule: If the Insurance Card is present in Athena, Insurance Eligibility is either Eligible or Unverified. See Insurance Eligibility map (draft).

Self Pay default (Athena Policy): When there is no insurance policy on file in Athena, the policy field defaults to Self Pay. For as long as that is true: GHL Insurance ID Front and Insurance ID Back must stay blank / unchecked (and be cleared if previously set), and there is nothing to update in Zenoti for this attribute family.

Integration behavior

Derive has_athena_insurance_policy (false when Athena defaults to Self Pay / no policy on file), plus has_athena_insurance_card_front and has_athena_insurance_card_back. If Self Pay / no policy: force-clear both GHL options and skip Zenoti (no-op). If a policy exists: mirror Front/Back image presence into Insurance Card Front → Insurance ID Front and Insurance Card Back → Insurance ID Back (set when present; clear when absent). Configure GHL so these options are hidden or non-editable for staff. Admin Check List ins_card = yes only when a policy exists and both Athena images exist (until/unless the ledger splits). Never copy image bytes to GHL or Zenoti.
